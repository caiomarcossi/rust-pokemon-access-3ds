# Speech

Every user-facing string is heard, not read, and usually while something else is happening. Write
for that: front-load the useful word and drop filler.

**Repeats.** A reader reports changes, so one showing is spoken once however long it stays on
screen. What the game shows again is spoken again: a second conversation with the same person is
heard, because a sighted player sees it.

**Policy lives in config.** What interrupts and what queues is configuration (speech category,
`[pa3ds.ui] interrupt`), because it is retuned during real play. A reader produces text and a category.
